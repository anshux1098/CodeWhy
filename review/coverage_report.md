## Definitions

Written in code comments (`backend/app/services/coverage.py`) and in `README.md` under "Coverage: what was checked":

- **touched**: PRs (non-noise and noise) whose changed files include the entity path.
- **analyzed**: sources with a completed extraction run (`ok` or `no_decision`), whether or not a verified decision came out of it.
- **noise-skipped**: sources removed by the noise filter.
- **not analyzed**: touched PRs that were neither analyzed nor noise-skipped.
- **verified decision**: `quote_verified=1`.

## Item 1 — the rebuild stores the coverage

`backend/app/services/coverage.py` computes the sets from the cache; `scripts/rebuild_graph.py` writes them:

- Each `CodeEntity` (file, module, config key): `prs_touching`, `prs_analyzed`, `prs_noise_skipped`, `prs_not_analyzed`, `verified_decisions`.
- The `Repository` node: `scope` text (branch, commit window, PR-touched file-path count, ingest caps), `prs_fetched`, `sources_analyzed`, `prs_noise_skipped`, `verified_decisions`.

Noise labelling was moved ahead of the coverage computation so a rule change is reflected in `prs_noise_skipped`. The rebuild stays replace-based; two rebuilds produce identical counts.

## Item 2 — refusals state what was checked

Wording in `evidence_gaps`, from the stored counts (exact strings):

- Case a, analyzed > 0: `N of M PRs touching this file were analyzed (K skipped as noise); no verified decision was found.`
- Case b, analyzed == 0 and M > 0: `This file is touched by M PRs but none were analyzed yet.`
- Case c, M == 0: `No PR in the ingested history touches this file.`
- `entity_not_found`: `This system covers <scope>; no matching file was found.`

Live examples:

- Case a, module entity `src/urllib3` (no `GOVERNS` edge): `76 of 147 PRs touching this file were analyzed (12 skipped as noise); no verified decision was found.`
- `entity_not_found`, `docs/user-guide.rst` (touched by PRs, no decision extracted): `This system covers urllib3/urllib3 at branch main, commits 2009-12-10..2026-10-01, 291 file paths touched by the fetched pull requests; ingest caps: max_ingestion_issues=100; no matching file was found.`
- `entity_not_found`, a nonexistent path: same scope wording.

No refusal claims that "no history exists"; each states the counts or the scope that was searched. A refusal makes no model call (pinned by a spy provider in `backend/tests/unit/test_coverage_wording.py`).

## Item 3 — a partial answer says how much was checked

For a full or partial answer on an entity with `prs_not_analyzed > 0`, `evidence_gaps` gains `N of M PRs touching this file were not analyzed.` The outcome, confidence and answer text are unchanged.

Live example, `src/urllib3/util/ssl_.py` (a full answer): `evidence_gap: 9 of 42 PRs touching this file were not analyzed.`

## Limitations

- Cases b and c are exercised by unit tests, not live. Every entity in the real graph either has a decision path or (the single module) has `analyzed > 0`, so no live question reaches the "touched but not analyzed" or "nothing touches this file" wording. A PR-touched file with no decision resolves to `entity_not_found` and reports the scope instead.
- Creating a `CodeEntity` for every PR-touched path was tried and reverted: with those nodes present, the loose token `use` in "why does the project use Kubernetes" matched `docs/user-guide.rst` and turned a correct `entity_not_found` into a `no_decision_path` refusal about the wrong file. A misleading refusal is worse than an honest "not found", so the entity set is left unchanged.
