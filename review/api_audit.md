graph in Neo4j, the cache at `data/ingest.sqlite3` (opened read-only), and a running
`uvicorn app.main:app` on the real graph (`DATA_SOURCE=graph`, `fixture: false`).

## Evidence detail

### 1. Repositories

Contract paths (`contract/openapi.json`): `/api/v1/repositories/{repository_id}`,
`/api/v1/repositories/{repository_id}/entities`, `/graph`, `/ask`,
`/api/v1/decisions/{decision_id}`, `/api/v1/health`, `/api/v1/health/dependencies`.
There is **no collection endpoint**.

`RepositoryResponse` (contract) required: `id,name,url,counts,fixture`;
`RepositoryCounts` required: `decisions,entities,pull_requests,commits`.

Real response `GET /api/v1/repositories/urllib3-urllib3` → HTTP 200:

```json
{"id":"urllib3-urllib3","name":"urllib3","url":"https://github.com/urllib3/urllib3",
 "counts":{"decisions":34,"entities":24,"pull_requests":299,"commits":735},"fixture":false}
```

The Repository node already carries the ingestion status the endpoint omits:

```text
{id:"urllib3-urllib3", full_name:"urllib3/urllib3", scope:"urllib3/urllib3 at branch main,
 commits 2009-12-10..2026-10-01, 291 file paths touched by the fetched pull requests;
 ingest caps: max_ingestion_issues=100", prs_fetched:294, sources_analyzed:96,
 prs_noise_skipped:70, verified_decisions:34}
```

No `outcome` or `time` field exists on the node either (only `created_at:"2026-01-01T00:00:00Z"`,
a constant). There is no SQLite fallback: `get_data_source` supports only `fixture` and
`graph`, and `GraphDataSource.get_repository` reads counts from the graph store.

### 2. Decisions

`GET /api/v1/decisions/{decision_id}` returns one `DecisionDetail`. There is no list
route, no `entity_id` filter, no `state` filter and no `limit` parameter anywhere in the
contract.

The entity payload is `Entity{id,type,label,path,decision_count}` (5 fields), e.g.
`{"id":"file:urllib3/urllib3:src/urllib3/util/ssl_.py","type":"File","decision_count":14}`.
It returns a **count only** — no decisions array and no `state`. The decisions for an
entity are reachable only by calling `/decisions/{id}` once per id (the ids are not even
listed; the `/graph` route is the only way to discover them).

### 3. Dates

`Decision` schema includes `recorded_at`, `effective_at`, `ended_at` (nullable), plus
`source: {type,number,url}`. Real responses:

```text
dec_6dee7648b9ef5416 (PR #3456): state=SUPERSEDED recorded_at=null effective_at=null ended_at=null
dec_ce303eb845540d38 (PR #3466): state=ACTIVE     recorded_at=null effective_at=null ended_at=null
```

`recorded_at` is neither the merge date nor the extraction time. The graph sets
`recorded_at = decisions.created_at`, and in the cache every verified decision has
`created_at = ''` and `decision_date = NULL` (34/34). The actual values live in
`raw_objects`:

| PR | `raw_objects.json.mergedAt` | `decisions.recorded_at` | `raw_objects.fetched_at` |
|----|----------------------------|-------------------------|--------------------------|
| #3456 | `2024-08-22T17:36:35Z` | `""` (API `null`) | `2026-10-14T13:20:42Z` |
| #3466 | `2024-09-03T09:10:49Z` | `""` (API `null`) | `2026-10-14T13:20:42Z` |

Extraction runs span `2026-10-15T09:05:30Z` → `2026-10-17T18:47:05Z`, so the empty date
is not the extraction time either. `decisions.source_author` is also `NULL` for every
verified decision.

### 4. Graph payload

Contract: `GraphResponse{nodes,edges,truncated(default false),fixture}`;
`GraphNode{id,label,type,props}`; `GraphEdge{source,target,type,rule}`.

Real response `GET /api/v1/repositories/urllib3-urllib3/graph?entity_id=file:urllib3/urllib3:src/urllib3/util/ssl_.py`
→ HTTP 200: 74 nodes / 97 edges; node types `CodeEntity 23, Evidence 22, Decision 14,
PullRequest 14, Repository 1`; **nodes with non-empty `props`: 0**. Edge types `GOVERNS 56,
SUPPORTED_BY 22, DECIDED_IN 14, CONTAINS 4, SUPERSEDES 1`; edges with a non-null `rule`: 1
(the `SUPERSEDES` edge, `rule:"1_revert_commit"`). `truncated:false`.

The properties that exist **on the graph nodes** but are dropped from the payload
(measured with Cypher):

- Repository: `id, repo, name, full_name, owner, url, default_branch, created_at, scope, prs_fetched, sources_analyzed, prs_noise_skipped, verified_decisions`.
- CodeEntity: `id, repo, name, path, entity_type, created_at, prs_touching, prs_analyzed, prs_noise_skipped, prs_not_analyzed, verified_decisions`.
- Decision: `id, repo, summary, decision_type, rationale, state, supersedes, superseded_by, rule, recorded_at, effective_at, ended_at, evaluated_at, quote_verified, source_id, source_type, source_number, source_url, embedding` — so **state, date and source URL exist on the node** but never reach the client.
- Evidence: `id, repo, decision_id, source_id, source_type, source_url, quote, author, timestamp, classification, claim, quote_verified, created_at` — the **quote exists** but is dropped.
- PullRequest/Issue/Document: `id, repo, number, title, url, state, created_at, text`.
- Commit: `id, repo, sha, subject, message, url, created_at`.

Supersession edges in the graph carry `rule, method, confidence, source_evidence_id,
review_state, evaluated_at`; only `rule` survives into `GraphEdge`.

Truncation: the schema field exists, but `GraphDataSource.get_graph` always passes
`truncated=False`. `GET /repositories/urllib3-urllib3/graph` (no entity) returned exactly
80 nodes with `truncated:false` — 80 is the default `max_graph_nodes` cap, so the response
is capped yet does not say so.

### 5. Repository ids

| Where | Value |
|-------|-------|
| Path `/{repository_id}` (repository, entities, graph, ask) | `urllib3-urllib3` (slug: `owner-name`) |
| `entity_id` query on `/graph` and body/entity id in `/ask` and responses | `file:urllib3/urllib3:src/urllib3/util/ssl_.py`, `module:urllib3/urllib3:src/urllib3`, `entity:<repo>:<name>` |
| `decision_id` path and in `decisions[]` | `dec_6dee7648b9ef5416` |
| Source/PR node id | `pr:urllib3/urllib3#3456` |

A separate display name does exist: `RepositoryResponse.name` (`"urllib3"`) and the node's
`full_name` (`"urllib3/urllib3"`) / `owner` (`"urllib3"`). The two id schemes differ only in
the slug: the repository is addressed as `owner-name` while every other id embeds the raw
`owner/name`. The graph holds a second Repository (`sqlalchemy-alembic`) with no coverage
props; without a list endpoint a client cannot discover it.

### 6. People

Cypher on the live graph:

```text
MATCH (p:Person) RETURN count(*)                 -> 0
MATCH ()-[e:AUTHORED]->() RETURN count(*)        -> 0
MATCH ()-[e:REVIEWED]->() RETURN count(*)        -> 0
PullRequest with an author property              -> 0
```

`PullRequest` node properties are only `{id, repo, number, title, url, state, created_at, text}`.
Citations returned by `/decisions/{id}` carry `author: null, timestamp: null`. `Person`,
`AUTHORED` and `REVIEWED` are declared in `app/stores/graph_store.py` as permitted, but the
rebuild never creates them.

The data is present in the cache, though: of the 34 verified decisions (each from a
distinct PR), `raw_objects` exists for **34/34**, carries a non-null `author` for **34/34**
(e.g. `sethmlarson`, `pquentin`, `jdufresne`, `jpevarnek`) and a `mergedAt` for **33/34**.
The raw PR payload also has `reviews` and `review_thread_comments` arrays, so reviewer
edges are derivable as well.
